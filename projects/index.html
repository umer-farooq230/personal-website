P-001

Regime Switching Engine for Financial Time Series

Python · ARIMA · GARCH · statsmodels · arch · Streamlit

Financial markets cycle between calm and volatile states. A model tuned for stability will misfire during high-volatility periods, and vice versa. This engine solves that by dividing a time series into 30-day windows, running a statistical volatility test on each, and switching the forecast model — ARIMA for stable periods, GARCH for volatile ones — automatically.

The business implication: a risk team or quant desk using this gets a forecast that is contextually appropriate to current market conditions rather than averaging across regimes. The engineering implication: the switching logic is deterministic and auditable, not a black box.

P-002

Intrusion Detection for MQTT / IoT Networks

Python · Random Forest · MLflow · SQL · scikit-learn · Jupyter

MQTT is the lightweight messaging protocol running most IoT infrastructure — smart meters, industrial sensors, connected devices. Anomalous traffic in these networks can signal an intrusion, but the traffic patterns are often noisy and imbalanced by class.

This project builds an end-to-end detection pipeline: raw data staged in SQL, cleaned and exported, then benchmarked across classical ML and deep learning methods. Random Forest outperformed LSTM autoencoders (which showed validation loss above 0.45 and unstable precision/recall), and unsupervised methods failed on class imbalance. The full experiment lifecycle is tracked in MLflow for reproducibility.

P-003

NL2SQL Fine-Tuning — LLaMA 3.1 8B

LLaMA 3.1 8B · Unsloth · LoRA · TRL · HuggingFace · GGUF

Most organisations have data in SQL databases and analysts who can not write SQL. The gap creates a dependency on engineering teams for routine data questions. This project fine-tunes Meta's LLaMA 3.1 8B to translate plain-language questions into executable SQL — with explanations — using the GretelAI synthetic text-to-SQL dataset.

Trained with 4-bit quantization and LoRA adapters to reduce memory requirements, making it viable on hardware below A100 class. Output format is GGUF (float16), ready for local deployment via llama.cpp or Ollama. The output includes both the query and a natural language explanation of what it does — reducing errors from incorrect query use.

P-004

Sentiment Analysis Pipeline — Google Play Reviews

Python · XGBoost · scikit-learn · YAML · Joblib

A structured, production-style sentiment classification pipeline on noisy app store review data. The key design decision: separate data processing, feature engineering, model training, and evaluation into distinct modules with a YAML config file — the same pattern used in real ML engineering teams.

Feature engineering went beyond word counts: review length, polarity/subjectivity scores, capitalization ratio, exclamation density, and app review frequency were tested as signals. The project treats model building as a hypothesis-testing exercise rather than a tuning exercise.
